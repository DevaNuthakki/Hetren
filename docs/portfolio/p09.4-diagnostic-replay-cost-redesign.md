# P09.4 Diagnostic Replay Cost Redesign

## Status

**DESIGN FROZEN FOR REVIEW — NO IMPLEMENTATION OR SCIENTIFIC COMPARISON AUTHORITY**

This design responds to the frozen P09.4A2C6C development calibration result.

A2C6C measured all existing P1-P5 probes as cost-degenerate:

- raw tool/environment interaction cost = 7 for every probe;
- workflow-step range = 17-17 for every probe;
- normalized cost = 1 for every probe;
- `B_full = 5`.

Therefore the current catalogue cannot identify the cost-aware C3-versus-C2
mechanism.

This document redesigns executable probe mechanics without assigning artificial
cost numbers.

---

## Scientific requirement

Any future probe-cost asymmetry must come from genuinely different executable
diagnostic work.

The redesign must not:

- assign arbitrary weights to P1-P5;
- count labels as work;
- add no-op calls;
- repeat calls solely to increase cost;
- use PASS/FAIL outcome to set price;
- use latent fault truth to set price;
- use workflow-step tie-breaking after observing equal tool cost;
- or alter experiment predictions merely to create C2/C3 separation.

---

## Root cause of A2C6C degeneracy

The existing development executor evaluates every diagnostic intervention by
running the entire workflow again.

Each probe therefore executes the same seven external tool/environment
interactions even though the intervention affects a different causal boundary.

The full-rerun executor is valid for diagnosis semantics, but it erases
differences in the amount of marginal work required by different experiments.

---

## Selected redesign: checkpoint/resume diagnostic replay

The selected direction is deterministic checkpoint/resume replay.

The original failed baseline workflow remains the common starting observation.

After a diagnostic experiment is selected, the environment reuses only
treatment-visible state that was already produced before the selected replay
boundary.

The intervention then re-executes the smallest causally sufficient downstream
workflow slice needed to produce a final diagnostic report.

The experiment cost is the number of new tool/environment interactions executed
during that diagnostic replay.

The already-observed baseline workflow is not charged again as if it were
new diagnostic work.

---

## Historical preservation

The existing full-rerun development path remains preserved for regression and
semantic-equivalence testing.

The redesign must be additive.

Existing A2C1-A2C6C evidence and historical closed-world diagnosis semantics
must not be rewritten.

The existing full-rerun probe result remains the reference diagnostic verdict
for each development case/probe cell.

---

## Treatment-visible checkpoint rule

A replay checkpoint may contain only state produced by ordinary baseline
execution up to the checkpoint boundary.

It must not contain:

- the latent fault label;
- an out-of-RFS flag;
- evaluator truth;
- hidden case assignment metadata;
- the correct diagnosis;
- or future workflow state that had not yet been produced at that boundary.

The planner must not inspect replay checkpoint internals when ranking
experiments.

Checkpoint state exists only to execute an already-selected intervention.

---

## Replay lineage requirement

Every diagnostic replay result must bind to:

- the baseline trace SHA-256;
- the selected experiment SHA-256;
- the replay checkpoint identifier;
- the treatment-visible checkpoint-state digest;
- every newly executed replay event;
- the resulting report;
- and the replay execution-evidence SHA-256.

This preserves auditable causal lineage without exposing evaluator truth.

---

## Frozen replay boundaries

The following replay boundaries are selected from the existing workflow
mechanisms.

They define what work is causally necessary for each experiment.

### P1 — canonical tool

Intervention:

`REPLACE_TOOL / strategy/tool-selection`

Resume boundary:

after service scope and context have been loaded, before strategy-dependent
filter execution.

New downstream external work must include:

- severity/filter execution;
- environment enrichment;
- policy validation;
- report construction.

Strategy selection and normalization remain internal deterministic operations.

### P2 — canonical parameter

Intervention:

`OVERRIDE_PARAMETER / strategy/parameter-transformation`

Resume boundary:

the same pre-filter boundary used by P1.

New downstream external work must include:

- severity/filter execution;
- environment enrichment;
- policy validation;
- report construction.

P1 and P2 are permitted to have equal measured cost.

### P3 — canonical prerequisite order

Intervention:

`REPLAY / orchestration/prerequisite-order`

Resume boundary:

after the baseline filter result exists, before the affected enrichment and
normalization sequence.

New downstream external work must include:

- environment enrichment;
- policy validation;
- report construction.

The normalization correction remains an internal deterministic operation.

### P4 — fresh context

Intervention:

`REPLAY / context/fresh-state`

Resume boundary:

after normalized incident rows exist but before policy validation consumes the
context.

New external work must include:

- fresh context retrieval;
- policy validation;
- report construction.

Previously produced normalized rows may be reused only because the current F4
mechanism does not consume context before validation.

If implementation analysis proves that assumption false, this design must stop
for review rather than silently reuse invalid state.

### P5 — environment response contract

Intervention:

`REPLAY / environment/response-contract`

Resume boundary:

after filtering but before environment enrichment.

New downstream external work must include:

- canonical environment enrichment;
- policy validation;
- report construction.

Normalization remains an internal deterministic operation.

---

## Structural cost expectation, not a measured result

The replay slices above imply a structural expectation that P1/P2 may require
more external interactions than P3/P4/P5.

This is not a calibrated result.

No numeric replay cost is frozen by this document.

The implementation must expose actual replay interaction counts, and a later
pre-measurement calibration protocol must derive costs from those counts.

If implementation or calibration does not produce genuine non-degenerate cost,
the negative result must again be retained.

---

## No artificial padding rule

Every external interaction counted as replay cost must contribute treatment
state or evidence that is consumed by the downstream replay.

An interaction must not exist solely to increase a probe's measured cost.

The implementation acceptance tests must show the ordered replay operations for
each probe.

Any extra operation without causal use invalidates the redesign.

---

## Semantic-equivalence requirement

For each of the existing seven development case classes and five probes:

`targeted_replay_verdict(case, probe)`

must equal:

`historical_full_rerun_verdict(case, probe)`

for all 35 cells.

The redesign is allowed to change marginal resource use.

It is not allowed to change what diagnostic evidence means.

---

## Expected known-fault semantics remain unchanged

The target probe remains:

- P1 for F1 tool-selection;
- P2 for F2 parameter-transformation;
- P3 for F3 sequencing/orchestration;
- P4 for F4 state/context;
- P5 for F5 environment-interaction.

The matching target probe must PASS.

Wrong-target probes must remain FAIL.

---

## Out-of-RFS semantics remain unchanged

The report-assembly control remains outside the five-hypothesis Rival Fault Set.

P1-P5 targeted replays must all remain FAIL for that control.

The opt-in open-set lifecycle must still require the final P5 confirmation and
terminate `INCONCLUSIVE` after the fifth contradictory FAIL.

Replay optimization must not reintroduce the A2C3 false-specific diagnosis.

---

## Isolation requirement

Every replay begins from an immutable baseline checkpoint snapshot.

One replay must not mutate another replay's starting state.

Running P1, then P4, then P1 again must reproduce the same P1 replay evidence
for identical inputs.

---

## Determinism requirement

For identical baseline, checkpoint, experiment, and intervention inputs, replay
must reproduce:

- verdict;
- final report;
- replay tool/environment interaction count;
- replay workflow-event count;
- replay trace/event digest;
- and replay execution-evidence digest.

---

## Resource-accounting rule

The redesigned executor must expose at least:

- replay tool/environment interaction count;
- replay event/step count;
- checkpoint identifier;
- replay operation sequence;
- baseline trace reference;
- and execution-evidence SHA-256.

The later calibration protocol will continue to use tool/environment interaction
count as the primary physical cost quantity unless a separate reviewed design
changes that rule before measurement.

---

## Planner boundary

This redesign changes experiment execution mechanics only.

It does not modify:

- hypothesis priors;
- experiment prediction tables;
- information-gain equations;
- information-gain-per-cost equations;
- posterior update semantics;
- open-set unique-confirmation semantics;
- or DiagnosisStatus.

C2 and C3 remain scientifically unexecuted.

---

## Proposed additive implementation surface

The preferred implementation is additive rather than a rewrite.

Candidate surfaces are:

`environments/agent/p09_4_multistep_incident.py`

for checkpoint/replay execution primitives, and:

`packages/engines/behavioral/p09_4_checkpoint_replay.py`

for the selection-neutral replay experiment executor.

A dedicated development integration test should compare all 35 replay verdicts
against the frozen full-rerun semantics.

The exact source layout may be adjusted during implementation if a smaller
maintainable boundary is discovered, but semantic requirements in this document
must remain unchanged.

### B — checkpoint truth boundary

- no out-of-RFS boolean enters treatment replay;
- no evaluator truth enters the replay executor;

### C — 35-cell semantic equivalence

- each matching F1-F5 probe still PASSes;

### D — replay lineage

- experiment digest is bound;

- P3 replay from the post-filter boundary;

- P5 replay from the pre-enrichment environment boundary;

- replay order does not change another replay;
- baseline snapshot remains immutable;

### G — open-set preservation

- F1-F5 still require RFS-unique support;
- F5 still requires P5 PASS;
- out-of-RFS still reaches evidence contradiction;

## Recalibration requirement

Successful replay implementation does not itself establish a new cost model.

Before measuring redesigned costs, P09.4 must freeze a new pre-measurement
calibration protocol tied to the redesigned executor.

The existing A2C6B/A2C6C records remain historical evidence of why redesign was
necessary.

They must not be overwritten.

---

## Future identifiability gate

After redesign implementation and a newly frozen calibration protocol:

- if measured replay costs are still equal, retain the second degeneracy
  result and stop;
- if at least two probes have genuinely different measured replay costs, the
  cost-aware mechanism becomes mechanically identifiable in principle;
- but C0-C3 scientific comparison remains blocked until final preregistration
  freezes populations, costs, budgets, seeds, arm semantics, scoring, and
  thresholds.

Non-degenerate cost is necessary for the intended C2-versus-C3 comparison.

It is not evidence that C3 is better.

---

## Claim boundary

This redesign is an engineering/research protocol change prompted by a negative
development calibration result.

It does not establish:

- H1 support;
- C3 superiority;
- lower real-world cost;
- lower latency;
- production efficiency;
- realistic-agent robustness;
- repair correctness;
- verification quality;
- or protected P09.4 validity.
