One-shot persistence readiness
------------------------------

The persistence core claims the protected batch identity before invoking the
caller-supplied generation-seed factory.

A STARTED disposition is persisted before generation-seed creation.

Once batch identity has been claimed, a failure consumes that identity rather
than silently permitting a reroll.

The generation seed is exactly 32 bytes and is persisted only in the
evaluator-side protected area.

A public cryptographic commitment binds the generation seed without publishing
the raw generation-seed bytes.

The protected public population manifest and evaluator-only hidden-assignment
manifest are persisted separately.

The persistence path materializes all 144 protected-population baselines and
requires every baseline to remain failing.

Public baseline evidence binds treatment-visible lineage such as trace,
report, and checkpoint hashes without publishing hidden stratum or expected
hypothesis labels.

Persistence uses restrictive directory/file permissions, filesystem syncing,
atomic new-file creation, and atomic disposition replacement.

Generation CLI readiness
------------------------

The production protected-population CLI exists and is development-qualified.

The CLI does not directly generate protected seed bytes.

It passes the secure generation-randomness capability to the frozen
persistence core.

Exactly one persistence-core invocation exists and it is confined to main().

The CLI and persistence core contain no scientific-arm execution path.

They contain no P1-P5 diagnostic replay execution path.

They contain no protected-evaluator execution path.

They contain no executable C1 treatment-seed path.

Generation-seed and C1-seed separation
--------------------------------------

The generation seed and C1 treatment-randomization seed are distinct frozen
protocol concepts.

K5C implements only the protected population generation-seed persistence
machinery and its guarded generation CLI.

K5C does not create the separately preregistered C1 seed.

K5C closure must not be interpreted as permission to reuse a generation seed
as a C1 seed or vice versa.
