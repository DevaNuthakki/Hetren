# P09.4 Checkpoint-Replay Cost Calibration Protocol

## Status

**PRE-CALIBRATION DEVELOPMENT PROTOCOL — NO C0-C3 SCIENTIFIC AUTHORITY**

This document freezes the dedicated calibration procedure for the additive
checkpoint/resume replay executor introduced by P09.4A2C6E.

No replay-cost calibration matrix is executed in this step.

No calibrated experiment cost is established by this document.

No final scientific budget or H1 threshold is established.

No protected P09.4 generation or execution is authorized.

---

## Methodological transparency

P09.4A2C6E implementation verification already exposed implementation-level
replay counters while proving that the redesigned execution path performs real
work.

Therefore this protocol is not represented as blind to the approximate
structural replay counts.

It is instead frozen before:

- the dedicated replay calibration matrix;
- replay-cost normalization;
- any candidate calibrated cost catalogue;
- any final P09.4 budget selection;
- any C0-C3 scientific comparison;
- any protected P09.4 population;
- and any protected P09.4 outcome.

The previously observed implementation counters remain implementation evidence,
not calibrated scientific costs.

The dedicated calibration result must be produced independently by the frozen
procedure below.

---

## Historical reason for recalibration

P09.4A2C6C calibrated the original full-rerun diagnostic executor and found
all five probes cost-degenerate.

That negative result remains historical evidence and must not be overwritten.

P09.4A2C6D then froze a checkpoint/resume redesign requiring cost differences,
if any, to arise only from genuinely different executable replay work.

P09.4A2C6E implemented that replay path and proved 35-cell semantic equivalence
with the historical full-rerun path.

The present protocol measures the redesigned path only.

---

## Calibration purpose

The calibration asks:

1. how much additional executable replay work each registered diagnostic probe
   performs after the common failed baseline already exists;
2. whether those marginal replay costs are deterministic across development
   cases;
3. whether at least two probes have genuinely different measured costs;
4. what exact positive-integer candidate costs follow from the frozen
   normalization rule;
5. and what mechanical budget landmarks follow from those candidate costs.

Calibration does not ask which treatment arm performs better.

---

## Common baseline accounting rule

The failed baseline workflow is common evidence available before experiment
selection.

Its historical execution cost is therefore excluded from experiment-specific
replay cost.

Only newly executed work after the selected replay checkpoint contributes to
the candidate diagnostic experiment cost.

This rule applies equally to every probe.

The baseline must not be selectively charged to one arm, one probe, one
verdict, or one latent fault class.

---

## Frozen development case catalogue

The dedicated calibration uses exactly seven development case classes:

- canonical no-fault control;
- F1 tool-selection;
- F2 parameter-transformation;
- F3 sequencing/orchestration;
- F4 state/context;
- F5 environment-interaction;
- out-of-RFS report-assembly control.

These are development fixtures.

Their labels may organize the calibration table but must not alter replay
execution cost.

---

## Frozen experiment catalogue

The calibration uses exactly the five existing replay experiments:

- P1 `p1-canonical-tool`;
- P2 `p2-canonical-parameter`;
- P3 `p3-canonical-prerequisite-order`;
- P4 `p4-fresh-context`;
- P5 `p5-environment-contract`.

No experiment may be added, removed, renamed, padded, shortened, or assigned a
manual cost during measurement.

---

## Frozen replay boundaries

The dedicated calibration must use the already-implemented A2C6E checkpoint
boundaries without modification.

P1 and P2 resume from the pre-filter boundary.

P3 and P5 resume from the post-filter boundary.

P4 resumes from the pre-validation boundary and refreshes context before
validation.

The calibration step may observe the resulting work.

It may not change these boundaries after seeing the resulting measurements.

---

## No-padding rule

Every counted replay tool interaction must correspond to an executed `TOOL_CALL`
whose output contributes to downstream replay state or evidence.

No no-op interaction may be added to increase measured cost.

No repeated call may exist solely to make one probe more expensive.

No internal deterministic operation may be relabeled as an external tool call
solely to create cost asymmetry.

---

## Frozen primary measurement matrix

The primary calibration matrix contains exactly:

`7 development case classes × 5 replay probes = 35 executions`

For each development case:

1. capture the deterministic A2C6E replay baseline;
2. build the existing development diagnosis problem from that baseline trace;
3. execute P1-P5 through `execute_checkpoint_replay`;
4. record the frozen resource fields described below.

The full 35-cell matrix is calibration evidence.

No cell may be removed because its verdict is inconvenient.

---

## Deterministic repeat

After the primary 35-cell matrix is complete, execute the same 35 cells again
with identical case, replay, experiment, sequence, and run-ID inputs.

The repeated structured records must exactly equal the primary records.

A repeat mismatch invalidates calibration.

The repeat is a reproducibility check.

It must not be averaged with the primary matrix.

---

## Frozen per-cell record

Each primary and repeat calibration cell must record:

- development case class;
- experiment key;
- replay checkpoint key;
- replay verdict;
- replay operation sequence;
- replay tool-interaction count;
- replay workflow-event count;
- baseline trace SHA-256;
- checkpoint-state SHA-256;
- experiment SHA-256;
- replay trace SHA-256;
- replay execution-evidence SHA-256.

Verdict is recorded for audit context only.

Verdict must not determine cost.

---

## Primary physical cost quantity

The primary experiment-cost quantity is:

**`P094ReplayRun.tool_interaction_count`**

This quantity counts newly executed replay `TOOL_CALL` events after the common
baseline checkpoint.

It is selected because it directly represents the additional external/tool-like
diagnostic work performed by the redesigned executor.

---

## Secondary structural quantities

The protocol also records:

- `P094ReplayRun.workflow_step_count`;
- `P094ReplayRun.replay_operations`;
- checkpoint key.

These values audit execution structure.

They do not override the primary physical cost quantity.

They must not be combined into a post-hoc weighted scalar.

---

## Per-probe raw cost rule

For each replay experiment E:

`raw_replay_cost(E) = max(tool_interaction_count for E across all seven development cases)`

The maximum provides a conservative ex ante declared price.

If the same probe produces different interaction counts on different cases, the
variation must be reported.

No case-specific cost may later be selected using hidden truth.

---

## Outcome-independence rule

A probe's price must not depend on PASS or FAIL.

If PASS and FAIL cells for the same probe use different replay interaction
counts, the conservative maximum across the frozen seven development cases is
used.

Latent fault identity must not determine declared experiment cost.

---

## Integer normalization rule

Let the five positive raw replay costs be:

`R1, R2, R3, R4, R5`

Compute:

`G = gcd(R1, R2, R3, R4, R5)`

Then:

`normalized_replay_cost(E) = raw_replay_cost(E) / G`

Every normalized cost must be an exact positive integer.

No rounding is allowed.

No clipping is allowed.

No hand-selected multiplier is allowed.

No secondary weighting is allowed.

---

## Degeneracy rule

If all five raw replay costs are equal, the redesigned replay catalogue remains
cost-degenerate.

In that case:

- the second degeneracy result must be retained;
- no artificial cost asymmetry may be introduced;
- C3 information-gain-per-cost remains mechanically indistinguishable from raw
  information gain under equal eligible experiments;
- C0-C3 scientific comparison remains blocked for the intended cost-aware
  mechanism claim;
- and the research design must stop for another review.

A second equal-cost result is valid evidence.

It must not be optimized away.

---

## Non-degenerate rule

If at least two probes have different frozen raw replay costs and the
deterministic repeat succeeds, the replay cost model is mechanically
non-degenerate.

This establishes only that a cost-aware selection mechanism is identifiable in
principle in the deterministic development environment.

It does not establish that C3 is better than C2.

It does not authorize C0-C3 execution.

---

## Mechanical budget landmarks

If the normalized replay cost catalogue is valid, calibration will compute:

`B_full = sum(normalized_replay_cost(P1..P5))`

`B_full` is the cost of executing every registered replay experiment once.

Calibration will also sort experiments by normalized cost ascending, breaking
ties by experiment key, and calculate:

`B_k = cumulative cost of the k cheapest experiments`

for k from 1 through 5.

These are mechanical affordability landmarks only.

They are not the final scientific evaluation budget.

---

## Open-set confirmation cost rule

Open-set confirmation is not free.

When a specific diagnosis requires a confirming experiment, that experiment
must consume its ordinary calibrated replay cost in any later scientific
protocol.

A future budget that cannot afford required confirmation must preserve the
existing `BUDGET_EXHAUSTED` semantics.

Calibration must not bypass this rule.

---

## Historical experiment cost fields

The existing development `DiagnosisProblem` currently carries historical
development `cost_units` values.

A2C6F does not mutate them.

A2C6G calibration must derive replay costs separately from the A2C6E execution
records.

Any later integration of calibrated replay costs into a scientific treatment
problem requires its own reviewed preregistration step.

Historical development behavior must remain reproducible.

---

## C0-C3 prohibition

The calibration step must not execute or summarize C0-C3 treatment performance.

It must not compute:

- C3 minus C0 accuracy;
- C3 minus C1 accuracy;
- C3 minus C2 accuracy;
- arm-specific diagnosis success;
- arm-specific false-specific rates;
- treatment support thresholds;
- or candidate H1 outcome conclusions.

The calibration step may only establish replay resource measurements and the
resulting mechanical cost model.

---

## Protected-work prohibition

No protected P09.4 case population may be generated during calibration.

No protected P09.4 treatment execution may occur.

No protected outcome may influence replay cost, normalization, budget
landmarks, or the degeneracy decision.

---

## Wall-clock exclusion

Wall-clock duration is not a calibrated scientific cost in this protocol.

CPU utilization, memory, cloud dollars, GPU usage, network latency, and machine
load are also excluded.

Those quantities do not currently have a controlled reproducible measurement
contract.

Adding one would require a separate reviewed design and, where meaningful new
technology is involved, explicit approval before introduction.

---

## Calibration validity requirements

A2C6G is mechanically valid only if:

- exactly 35 primary cells execute;
- exactly 35 deterministic-repeat cells execute;
- primary and repeat structured records are exact;
- every cell remains bound to baseline, checkpoint, experiment, trace, and
  execution evidence;
- all recorded tool interactions correspond to real executed replay work;
- no no-op padding occurs;
- costs follow the frozen maximum rule;
- normalization follows the exact GCD rule;
- no cost depends on verdict or latent truth;
- historical A2C6C evidence remains unchanged;
- the A2C6D design remains unchanged;
- the A2C6E implementation remains unchanged;
- P09.3 remains immutable;
- and the full repository regression remains green.

---

## Calibration stop conditions

A2C6G must stop before any scientific comparison if:

- the 35-cell matrix is incomplete;
- deterministic repeat differs;
- lineage is incomplete;
- execution accounting cannot be reproduced;
- a replay operation exists only for padding;
- cost depends on PASS/FAIL;
- cost depends on latent fault truth;
- manual weighting would be required;
- or all five measured raw replay costs are equal.

A stop is a valid research result.
